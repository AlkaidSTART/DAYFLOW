# 个人效率工作台 App — 产品需求文档（PRD）

> 产品名称：DAYFLOW
> 产品版本：V1.0
> 产品形态：Android 原生体验的跨平台移动应用（Expo / React Native）
> 目标用户：大学生
> 核心理念：让用户每天更专注地管理时间、任务与生活开支。
> 产品原则：Local First、轻量、高效、低打扰。

## 1. 产品概述

### 1.1 产品定位

一款面向大学生的个人效率工作台，将每日任务管理、番茄专注计时和个人生活记账整合到一个统一的移动端应用中。

它不是传统的 Todo List，也不是单一番茄钟或记账软件，而是一个围绕个人日常生活展开的轻量工作台。

用户每天打开 App，即可完成：

- 确定今天最重要的事情。
- 进入专注模式，减少干扰。
- 记录生活开支，了解预算剩余情况。
- 回顾当天的时间与任务完成情况。

### 1.2 核心价值

| 维度     | 解决的问题                   | 产品价值                    |
| -------- | ---------------------------- | --------------------------- |
| 任务管理 | 每天事情太多，不知道先做什么 | 聚焦每日最重要的三件事      |
| 时间管理 | 容易分心，缺乏持续专注能力   | 通过 TimePulse 提供专注计时 |
| 财务管理 | 不清楚生活费花在哪里         | 预算、记账、消费统计        |
| 日常复盘 | 缺少对一天的总结             | 汇总任务、专注和消费数据    |

### 1.3 产品设计原则

1. **Local First**：所有核心数据默认保存在设备本地。
2. **低操作成本**：常用功能尽量在两次点击内完成。
3. **克制的信息密度**：不堆砌数据，不制造无意义的复杂度。
4. **正向激励**：通过进度和反馈帮助用户建立习惯，而不是制造焦虑。
5. **长期使用**：视觉风格稳定、操作一致，适合每天打开。

## 2. 用户画像

### 2.1 目标用户

主要面向大学生，兼顾有个人效率管理需求的年轻用户。

典型场景：

- 大学生每天需要安排课程、学习、作业和个人事务。
- 备考用户需要长时间专注。
- 有固定生活费，需要控制每月开支。
- 希望通过数据了解自己的时间利用情况。

### 2.2 用户核心诉求

| 用户诉求             | 对应功能        |
| -------------------- | --------------- |
| 今天应该做什么？     | Today 每日任务  |
| 如何保持专注？       | Focus 专注计时  |
| 还剩多少生活费？     | Wallet 预算管理 |
| 最近效率怎么样？     | 每日数据汇总    |
| 换手机或重装怎么办？ | 本地备份与恢复  |

## 4. 功能需求

> 本文只描述用户可感知的行为与业务规则；字段结构、存储方式等实现细节见 [tech-stack.md](./tech-stack.md) 第 4 章。

## 4.1 Today — 每日工作台

### 功能定位

Today 是用户打开应用后的默认首页。

核心目标：帮助用户明确当天最重要的事情。

### 4.1.1 每日 Top 3

用户可以选择当天最重要的三件事情。

功能要求：

- 新建任务。
- 编辑任务。
- 删除任务。
- 调整任务顺序。
- 标记任务完成。
- 取消完成状态。
- 显示当天任务完成进度。
- 超过三件任务时，仍可添加普通任务，但 Top 3 保持独立。

业务规则：

- 当天 Top 3 最多 3 条，已满时不能继续标记为 Top 3，需提示用户先取消一条。
- Top 3 与普通任务共用同一任务列表，Top 3 置顶展示。
- 任务归属于某一自然日（用户本地时区的日期），跨天后首页展示新一天的任务。
- 未完成的任务不会自动顺延到第二天，避免产生任务堆积焦虑。

### 4.1.2 每日进度

展示：

- 已完成任务数。
- 总任务数。
- 完成百分比。
- Top 3 完成情况。

计算方式：

完成率 = 已完成任务数 / 总任务数 × 100%

当没有任务时显示空状态，不显示 NaN 或错误百分比。

### 4.1.3 Focus 摘要

Today 首页展示当天专注情况：

- 今日专注时长。
- 完成专注次数。
- 最近一次专注记录。

点击后跳转 Focus 页面。

### 4.1.4 每日复盘

MVP 提供简单的每日复盘：

- 今日完成了什么。
- 今日专注时长。
- 今日待完成任务。
- 可选文字备注。

不引入复杂的 AI 总结。

### 4.1.5 交互要求

- 任务完成与取消完成必须即时反馈，不允许出现「点了没反应」。
- 删除任务需提供撤销机会或二次确认。
- 空状态需给出明确的下一步操作入口（新建第一个 Top 3）。

## 4.2 Focus — TimePulse 专注中心

### 功能定位

将现有 TimePulse 的核心计时能力整合进工作台。

Focus 不是简单的倒计时页面，而是统一的时间管理中心。

### 4.2.1 计时模式

MVP 支持：

- 专注时间。
- 短休息。
- 长休息。

默认配置：

| 类型   | 默认时长 |
| ------ | -------: |
| 专注   |  25 分钟 |
| 短休息 |   5 分钟 |
| 长休息 |  15 分钟 |

用户可以在设置中修改时长。

### 4.2.2 计时操作

- 开始。
- 暂停。
- 继续。
- 结束。
- 跳过休息。
- 切换模式。

结束专注时，记录本次有效专注数据。

异常退出、进程回收或手机重启后，必须根据持久化时间戳恢复计时状态，恢复后的剩余时间必须与实际经过时间一致。

### 4.2.3 任务关联

用户可以在开始专注前关联 Today 中的任务。

- 关联为可选项，不关联也可以开始专注。
- 关联后，该次专注记录归属于对应任务，用于后续统计。
- 任务被删除后，历史专注记录仍然保留，只解除关联。

### 4.2.4 后台计时

真实剩余时间必须以系统时间为准，不能依赖应用前台运行或定时器累加。

产品层面的承诺：

- 切换应用、熄屏、强制结束进程、手机重启后重新打开，剩余时间均正确。
- 计时期间的界面刷新只影响显示，不影响真实计时结果。

### 4.2.5 触觉反馈

在以下操作提供轻量震动：

- 开始专注。
- 暂停。
- 完成专注。
- 完成任务。
- 重要操作确认。

必须允许用户关闭触觉反馈。

### 4.2.6 本地通知

- 专注结束通知。
- 休息结束通知。
- 用户主动开启的提醒。

通知权限被拒绝时，不能影响核心计时功能。

### 4.2.7 交互要求

- 计时进行中，主操作按钮始终可见且明确（开始 / 暂停 / 继续）。
- 结束专注需二次确认，避免误触丢失本次记录。
- 模式切换在计时进行中不可直接生效，需先结束或确认放弃当前计时。

## 4.3 Wallet — 预算与记账

### 功能定位

面向大学生生活费管理的轻量预算 + 完整记账模块。

既满足快速记一笔，也能查看当月资金使用情况。

### 4.3.1 预算管理

默认按自然月统计。

展示：

- 月初预算。
- 已支出金额。
- 剩余金额。
- 预算使用率。
- 每日建议可用金额。

预算计算：

剩余预算 = 月度预算 - 当月支出

预算使用率 = 当月支出 / 月度预算 × 100%

每日建议可用金额：

剩余预算 / 当月剩余自然日数（含当天）

当预算为零或剩余天数为零时，需要进行边界处理：

- 未设置预算时，展示引导设置预算的入口，不展示除法结果。
- 预算为 0 时，使用率按 0% 处理并提示设置预算。
- 支出超过预算时，剩余金额为负数，使用率可超过 100%，以醒目但不羞辱用户的方式展示。

### 4.3.2 记账功能

支持：

- 新增支出。
- 新增收入。
- 编辑账单。
- 删除账单。
- 选择分类。
- 选择日期。
- 添加备注。

金额精度要求：所有金额以「分」为单位计算与存储，界面展示保留两位小数，禁止使用浮点数累加。

### 4.3.3 默认分类

支出：

- 餐饮
- 交通
- 购物
- 学习
- 娱乐
- 日用品
- 住宿
- 其他

收入：

- 生活费
- 奖学金
- 兼职
- 其他

支持用户自定义分类。

分类被账单引用时不允许直接删除，需引导用户先迁移或归档该分类下的账单。

### 4.3.4 统计

MVP 支持：

- 本月收入。
- 本月支出。
- 本月结余。
- 分类支出占比。
- 最近账单列表。

### 4.3.5 预算提醒

当预算使用率达到用户设置的阈值时，展示提示。

默认阈值可设为 80%。

不应频繁弹窗打扰用户：

- 每个自然月同一阈值只提醒一次。
- 提醒以页面内提示条为主，不使用强制弹窗。

## 5. 本地数据与备份

### 5.1 数据策略

采用 Local First 架构：

- 所有核心业务数据默认存储在设备本地。
- 无需注册登录即可使用。
- 不依赖服务器完成核心功能。
- 离线情况下可正常使用。
- 不在后台未经授权上传用户数据。

### 5.2 数据备份

支持导出完整 JSON 备份。

备份内容：

- 任务。
- 专注记录。
- 计时配置。
- 预算。
- 账单。
- 分类。
- 用户设置。
- 数据库版本信息。

恢复时：

1. 校验备份文件结构。
2. 校验数据版本。
3. 检查字段合法性。
4. 提示用户恢复将如何处理当前数据。
5. 执行事务式导入。
6. 失败时回滚。

MVP 可以采用完整替换恢复，不做复杂的多设备合并。

### 5.3 卸载提醒

Android 卸载应用通常会删除应用私有数据。

因此需要在设置中提供显眼的数据导出入口，并提醒用户卸载前备份。

## 6. 非功能需求

> 实现方式见 [tech-stack.md](./tech-stack.md) 第 7 章，本章只定义产品可感知的质量标准。

### 6.1 性能

- 首页应快速展示，冷启动后可立即看到当天任务，不出现长时间空白。
- 长列表滚动流畅，不卡顿。
- 动画保持流畅，交互不出现掉帧。
- 后台计算不阻塞界面操作。

### 6.2 稳定性

- 计时状态持久化。
- 账单不会因为重复点击而重复入账。
- 金额计算保证精度。
- 应用升级不得主动清空数据库。
- 数据库升级失败不得造成无保护的数据破坏。

### 6.3 隐私

- 本地数据默认不上传。
- 不收集不必要的个人信息。
- 通知和权限按需申请。
- 数据导出由用户主动触发。

## 8. 验收标准

### Today

- 可以创建和完成任务。
- 每日 Top 3 数量受到限制。
- 任务数据重启后仍存在。
- 日期切换正确。
- 无任务时进度区域展示空状态而非错误数值。

### Focus

- 可以开始、暂停、继续、结束。
- 后台运行和进程回收后能够恢复。
- 专注记录时间正确。
- 通知权限关闭时仍能计时。
- 暂停时间不计入实际专注时长。

### Wallet

- 支出、收入可以正常记录。
- 金额精度正确（连续累加 0.01 不产生误差）。
- 预算剩余金额计算正确。
- 账单修改后统计同步更新。
- 未设置预算时不出现除零或异常展示。

### 数据安全

- 强制结束 App 后数据不丢失。
- 升级安装后数据不丢失。
- 备份文件可以恢复。
- 恢复失败时当前数据保持不变。

### 发布

- GitHub Actions 可以自动构建 APK。
- 新旧 APK 使用相同签名证书。
- applicationId 保持一致。
- versionCode 每次发布递增。
- 新版 APK 可以直接覆盖安装。

## 9. 产品成功指标

MVP 阶段重点关注：

- 次日留存率。
- 7 日留存率。
- 每日任务创建率。
- 每日任务完成率。
- 每日专注次数。
- 每周记账天数。
- 用户主动打开次数。

核心北极星指标：

**每周有效使用天数**：一周内用户至少完成一次任务、专注或记账操作的天数。

> 说明：Local First 模式下不采集远程埋点。上述指标在 MVP 阶段通过本地统计数据与用户主动导出获得，或仅作为产品方向参考，不引入第三方统计 SDK。
